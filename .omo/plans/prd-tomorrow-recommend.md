## AI 速读卡

```
产品名：OJBetter 明日推荐系统
一句话：基于学生历史提问的知识点、难度、算法标签，AI 分析所处阶段并推荐明日刷题
目标用户：8-16 岁信奥赛学生 + 家长/教练
核心场景：学生做完题后，系统分析掌握情况，次日自动推荐薄弱知识点的针对性练习
平台：Chrome 扩展（Side Panel + Settings Page）
关键差异：CF Rating 分数制难度 + hintLevel 真实掌握度分析；推荐每道题附可点击超链接直达 OJ 题目页
P0功能：结构化记录知识点/难度(CF Rating)/标签 → 阶段分析 → 明日推荐题单（含 OJ 链接）
技术栈：chrome.storage.local + 现有 AI 流式架构 + OJ 链接生成
风险项：第三方 OJ 链接稳定性；AI 估计的 CF Rating 与真实难度可能存在偏差
```

## 第一章：产品概述

### 1.1 产品定义

在 OJBetter 现有"明日推荐"功能基础上，建立**结构化知识图谱数据库**——不再仅靠正则提取粗粒度 topic，改为记录每次提问涉及的**具体知识点、题目难度（CF Rating 800~3500）、算法标签（如 DP、贪心、二分）**，并以此作为 AI 分析学生所处学习阶段的依据，生成精确到薄弱知识点的明日推荐题单，题目来源为洛谷、Codeforces、AtCoder。

> 硬约束：不记录题目原文内容（fullQuestion/question字段除外，但新模块不再新增原始题目文本）
> 推荐默认：知识图谱数据与原 history 共存但不混用，新开存储空间
> 发挥空间：后续可接入更多 OJ 平台

### 1.2 目标用户画像

| 角色 | 需求 | 痛点 |
|------|------|------|
| 学生（8-16岁） | 知道明天该练什么，不盲目刷题 | 做完题不知下一步方向 |
| 家长 | 了解孩子弱项，监督练习 | 看不懂算法术语，需要清晰结论 |
| 教练/老师 | 批量掌握学生情况，针对性布置作业 | 一个个看太慢，需要自动化分析 |

### 1.3 可行性边界

**已有基础：**
- `history.js`：按天分片，已有 `topic`、`hintLevel`、`chatHistory` 字段
- `learning-plan/generator.js`：已有流式生成明日计划 + 题单
- 侧边栏已有 📅 按钮
- AI 流式架构已成（stream-fetcher + keepalive）

**新增范围：**
- 知识图谱存储层（新 key 空间，不与原有 history 混用）
- 知识点提取/标注逻辑（在每次 AI 回答后自动结构化产出）
- 阶段分析 + 推荐引擎（基于图谱数据做 AI prompt）
- OJ 题目链接生成器（洛谷/CF/AtCoder 已知题号 → URL）

**非目标：**
- 不替代现有 history 存储
- 不做社区/排行榜功能
- 不爬取 OJ 题目全文（仅记录题号/URL/难度标签）

## 第三章：核心模块详细设计

### 模块 M1：知识图谱记录器

**每次 AI 回答结束后，自动结构化提取本次对话涉及的知识信息。**

```
┌─────────────────────────────────────────────────────┐
│              知识图谱记录器流程                        │
│                                                      │
│  学生提问 → AI 回答 → 回答结束回调                     │
│                           │                           │
│                           ▼                           │
│  ┌─ 提取知识点 ─────────────────────────────────┐    │
│  │  输入：problemText + chatHistory + AI回答     │    │
│  │  处理：AI 非流式调用，提取：                   │    │
│  │    • knowledgePoints: ["DP", "0-1背包"]       │    │
    │  │    • difficulty: 1200                            │    │
    │  │    • tags: ["入门DP", "背包问题"]              │    │
│  │    • mastery: "hintLevel最后值"               │    │
│  │  输出：结构化 JSON 对象                        │    │
│  └────────────────────────────────────────────┘    │
│                           │                           │
│                           ▼                           │
│  ┌─ 存储 ─────────────────────────────────────────┐  │
│  │  key: "knowledge_graph"                         │  │
│  │  数据结构见第五章                                 │  │
│  └────────────────────────────────────────────┘    │
│                           │                           │
│                           ▼                           │
│  ┌─ 聚合统计 ──────────────────────────────────┐    │
│  │  更新知识点掌握度统计（按标签聚合）             │    │
│  │  更新薄弱点排序                                │    │
│  └────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────┘
```

**正常流程：**
1. AI 流式回答完成（onDone 回调）
2. 背景触发一次非流式轻量 AI 调用，传入 `problemText` + 最后几轮对话
3. AI 返回结构化 JSON：知识点列表、难度、算法标签
4. 写入 `knowledge_graph` 存储（新增条目）
5. 更新聚合统计（按知识点名称的掌握度均值）

**失败路径 F1（AI 提取失败）：**
- AI 返回非法 JSON 或空值 → 跳过本次记录，不影响已有数据
- 用户可见：无感知（静默失败）

**失败路径 F2（存储满）：**
- 单日超出 100 条 → 丢弃最旧记录，保留最近 100 条
- 总条目超 5000 → 自动压缩（合并相同知识点，保留均值）

**状态定义：**
- `idle`：等待下次对话
- `extracting`：AI 正在提取知识点
- `extracted`：提取完成，已存储
- `failed`：提取失败（跳过）

**待决问题：**
- 首次使用冷启动：无历史数据时，推荐系统应显示"再做几道题，我就了解你了"的引导态
- 知识点标签体系是动态的（AI 自由输出归一化后存储），还是固定词表？→ 推荐默认：AI 自由输出，后期用统计聚合做归一化

### 模块 M2：阶段分析引擎

**以知识图谱数据为输入，AI 分析学生当前所处竞赛阶段、薄弱环节。**

```
┌─────────────────────────────────────────────────────┐
│              阶段分析引擎流程                        │
│                                                      │
│  📅 按钮点击 / 定时触发                               │
│           │                                           │
│           ▼                                           │
│  ┌─ 加载数据 ──────────────────────────────────┐    │
│  │  从 knowledge_graph 读取所有记录               │    │
│  │  聚合：按知识点统计 count + avgHintLevel        │    │
│  └────────────────────────────────────────────┘    │
│           │                                           │
│           ▼                                           │
│  ┌─ AI 分析 ───────────────────────────────────┐    │
│  │  非流式调用（快速，3-5秒）                      │    │
│  │  输入：聚合统计数据 + 学生总题数                │    │
│  │  输出结构化分析：                               │    │
│  │  • currentStage: "rating_1200_1400"            │    │
│  │  • weakPoints: ["DP", "图论"]                  │    │
│  │  • strongPoints: ["模拟", "排序"]              │    │
│  │  • stageConfidence: 0.85                      │    │
│  └────────────────────────────────────────────┘    │
│           │                                           │
│           ▼                                           │
│  ┌─ 缓存结果 ──────────────────────────────────┐    │
│  │  key: "stage_analysis"                        │    │
│  │  缓存至次日 0:00 过期                           │    │
│  └────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────┘
```

**正常流程：**
1. 用户点击 📅 或系统每日首次打开侧边栏
2. 读取知识图谱数据，聚合统计
3. 若数据量 < 3 条 → 返回"数据不足"引导态
4. 数据充足 → AI 非流式分析，返回结构化阶段评估
5. 缓存结果

**失败路径 F1（AI 分析超时）：**
- 超过 10 秒无响应 → 显示"分析超时，请重试"
- 使用上次缓存结果降级

**失败路径 F2（数据不足）：**
- 总记录 < 3 条 → 展示引导提示："再多练习几道题，我就能给你出推荐了✊"

**依赖：** 模块 M1（知识图谱数据）

### 模块 M3：明日推荐生成（学习建议 + 练习题）

**基于阶段分析，AI 按"先给学习建议，再列练习题"的格式输出推荐——每道题必须附带可点击的 OJ 超链接。**

```
┌─────────────────────────────────────────────────────┐
│              推荐生成流程                             │
│                                                      │
│  阶段分析完成（或点击"刷新推荐"）                      │
│           │                                           │
│           ▼                                           │
│  ┌─ 构建推荐 Prompt ───────────────────────────┐    │
│  │  硬约束：AI 必须输出精确的题号/ID                   │    │
│  │  （如 P1048、1741A、abc283_d），                  │    │
│  │  不可只写题目名或模糊描述                          │    │
│  │  输入：                                          │    │
│  │  • 学生当前阶段（rating 范围）                  │    │
│  │  • 薄弱知识点（DP、图论）                     │    │
│  │  • 已练题目知识点分布                         │    │
│  │  • hintLevel 趋势（进步/退步）                │    │
│  └────────────────────────────────────────────┘    │
│           │                                           │
│           ▼                                           │
│  ┌─ AI 流式生成 ───────────────────────────────┐    │
│  │  使用现有 streamPlan 基础设施（stream-fetcher） │    │
│  │  输出分两段：                                    │    │
│  │  ① 📝 学习建议（2-3句，指出薄弱点+改进方向）    │    │
│  │  ② ✏️ 练习题（3-5道，每道严格按以下格式）       │    │
│  │     「{OJ平台} {题号} {题目名}」                 │    │
│  │     如「洛谷 P1048 采药」或「CF 1741A」          │    │
│  │  无题号=不计入有效推荐                           │    │
│  └────────────────────────────────────────────┘    │
│           │                                           │
│           ▼                                           │
│  ┌─ OJ 链接生成 + 验证 ───────────────────────┐    │
│  │  解析 AI 输出的 OJ + 题号 → 生成可点击 URL      │    │
│  │  洛谷: https://www.luogu.com.cn/problem/P1048  │    │
│  │  CF:   https://codeforces.com/problemset/1741A │    │
│  │  AtC:  https://atcoder.jp/contests/abc283/...  │    │
│  │  并发 HEAD 请求验证题号是否存在                   │    │
│  │  ├─ 200 ✅ → 可点击                             │    │
│  │  └─ 404 ❌ → 灰显+标记"题号不存在"               │    │
│  │  无题号 → 整条推荐标记为"链接失效"                │    │
│  └────────────────────────────────────────────┘    │
│           │                                           │
│           ▼                                           │
│  ┌─ 渲染展示 ─────────────────────────────────┐    │
│  │  侧边栏推荐面板，顶部学习建议、底部练习题列表：      │    │
│  │                                                │    │
│  │  ┌─ 📝 学习建议 ─────────────────────┐        │    │
│  │  │  你最近的 DP 还不太熟练，明天集中       │        │    │
│  │  │  练一下 0-1 背包和背包变种题。         │        │    │
│  │  │  建议先复习状态转移方程再做题。         │        │    │
│  │  └───────────────────────────────────┘        │    │
│  │                                                │    │
│  │  ┌─ ✏️ 练习题 ───────────────────────┐        │    │
│  │  │  ✅ 洛谷 P1048 采药 [DP/1200]     │        │    │
│  │  │     <a href="URL">点击做题 ↗</a>  │        │    │
│  │  │  ❌ 洛谷 P99999 ???               │        │    │
│  │  │     ❓题号不存在（灰显）           │        │    │
│  │  │  ⏳ CF 1741A ... 验证中...         │        │    │
│  │  └───────────────────────────────────┘        │    │
│  └────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────┘
```

**正常流程：**
1. 阶段分析完成后自动触发（或手动刷新）
2. AI 流式生成两段内容：先输出📝学习建议（2-3 句），再输出✏️练习题列表（每道含 OJ 平台 + 精确题号）
3. OJ 链接生成器将题号解析为 URL
4. **并发 HEAD 请求验证每个 URL 是否有效（200 OK）**
5. 有效 ✅ → 渲染为可点击超链接；无效 ❌ → 灰显+标记"题号不存在"
6. 渲染到推荐面板：顶部学习建议区（纯文本）+ 底部练习题列表（每道含超链接）

**失败路径 F1（AI 未输出题号/题号格式错误）：**
- 链接生成器无法解析 → 该条目显示为灰色文字 + "🔗待搜索"标记
- 用户仍可见题目描述，但需手动搜索
- prompt 中强化约束：无题号推荐判为无效输出
- 不存在题号验证步骤（连 URL 都生不成，无需验证）

**失败路径 F2（AI 推荐已做过的题目）：**
- 去重逻辑：对比已有 history 中的题目 URL，重复则过滤
- 在 prompt 中注明"不要推荐学生已做过的题目"
- 同时提供历史已做题目的题号列表作为参考

**失败路径 F3（OJ 链接失效/页面不存在）：**
- 题号生成 URL 后用 HEAD 请求验证 HTTP 状态码
- 200 → 有效 ✅ / 404 → 标记"题目不存在" ❌
- 验证失败整条推荐灰显，标注"❓题号无效"

**状态定义：**
- `loading`：正在生成推荐（骨架屏）
- `ready`：推荐就绪（学习建议 + 全部练习题可点击）
- `partial`：部分练习题验证失败（学习建议照常显示，失效题目灰显）
- `stale`：昨日缓存，可刷新

**依赖：** 模块 M2（阶段分析结果）

### 模块 M4：OJ 链接生成器 + 题号验证器

**将 AI 输出的自然语言题号转换为标准化 URL，并验证题目是否存在。**

```
┌─────────────────────────────────────────────────────┐
│              OJ 链接生成 + 验证流程                   │
│                                                      │
│  AI 输出: "洛谷 P1048 采药"                           │
│           │                                           │
│           ▼                                           │
│  ┌─ 正则解析 ──────────────────────────────────┐    │
│  │  OJ=洛谷, 题号=P1048                         │    │
│  └────────────────────────────────────────────┘    │
│           │                                           │
│           ▼                                           │
│  ┌─ URL 模板 ──────────────────────────────────┐    │
│  │  https://www.luogu.com.cn/problem/P1048      │    │
│  └────────────────────────────────────────────┘    │
│           │                                           │
│           ▼                                           │
│  ┌─ HTTP HEAD 验证 ────────────────────────────┐    │
│  │  fetch(URL, method: HEAD)                     │    │
│  │  ├─ 200 OK → ✅ 有效                         │    │
│  │  └─ 404/其他 → ❌ 题号不存在                   │    │
│  └────────────────────────────────────────────┘    │
│           │                                           │
│           ▼                                           │
│  ┌─ 状态写入 ──────────────────────────────────┐    │
│  │  valid: true  → 渲染为可点击超链接             │    │
│  │  valid: false → 灰显+标记"❓题号不存在"         │    │
│  └────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────┘
```

**输入→输出示例：**
```
"洛谷 P1048 采药"     → https://www.luogu.com.cn/problem/P1048     → HEAD 200 ✅
"Codeforces 1741A"    → https://codeforces.com/problemset/problem/1741/A → HEAD 200 ✅
"AtCoder ABC 283 D"  → https://atcoder.jp/contests/abc283/tasks/abc283_d → HEAD 200 ✅
"洛谷 P99999"         → https://www.luogu.com.cn/problem/P99999     → HEAD 404 ❌
```

**规则表：**

| 关键词 | URL 模板 | 示例 |
|--------|----------|------|
| 洛谷/Luogu/P\d+ | `https://www.luogu.com.cn/problem/{id}` | P1048 |
| Codeforces/CF/\d+[A-Z] | `https://codeforces.com/problemset/{id}` | 1741A |
| AtCoder/ABC/ARC/AGC | `https://atcoder.jp/contests/{contest}/tasks/{task}` | abc283/abc283_d |
| 其他 | 降级为纯文本，不加链接 | — |

**验证方式：**
```javascript
async function verifyProblemUrl(url) {
  try {
    const resp = await fetch(url, { method: 'HEAD', signal: AbortSignal.timeout(5000) });
    return resp.ok; // 200-299 → true, 404 → false
  } catch {
    return false; // 超时/网络错误 → 标记为"待确认"（timeout 不判 false）
  }
}
```

> 硬约束：所有推荐题目必须经过 URL 模板生成 + HTTP HEAD 验证两步。验证失败（404）的条目灰显不可点击，标记"❓题号不存在"。网络超时不判死刑，标"⏳待确认"。
> 推荐默认：5 个推荐并发验证，超时 5 秒，不阻塞面板渲染（先展示 loading 占位，验证完成逐个点亮）
> 关键决策：用 HEAD 而非 GET——只查存在性，不下载页面内容，轻量快速，OJ 服务器友好。

## 第四章：超越竞品的差异化功能

### 4.1 基于 hintLevel 的真实掌握度判断

大多数刷题推荐系统仅根据"做过/没做过"二分判断。OJBetter 特有的 `hintLevel`（1=思路提示，2=流程图，3=伪代码）记录了学生需要多少帮助才能解出题目——这是比"AC/WA"更精细的掌握度指标。

- 同一知识点多次 hintLevel=1 → 掌握良好
- 同一知识点 hintLevel 从 1→3 增长 → 遇到困难，亟需练习
- 多知识点题目中每个子标签的 hintLevel 可拆分（需要 prompt 设计）

### 4.2 渐进式知识图谱

冷启动时给出"再做 X 题即可解锁推荐"的进度条，让用户有期待。每做一题，图谱自动更新，推荐精准度逐步提升——这是与生硬"做满 N 题才出推荐"不同的人性化设计。

### 4.3 多 OJ 聚合推荐

单一 OJ 的题库有限。洛谷适合国内竞赛（CSP/NOIP），CF 适合练习思维速度，AtCoder 适合入门。
根据学生阶段（CF Rating 范围）自动选择最合适的 OJ 来源：
- ≤800：AtCoder ABC 前3题 + 洛谷入门
- 800~1200：洛谷普及- + CF Div.3 A~C
- 1200~1600：洛谷普及/普及+ + CF Div.3 D~F
- 1600~2000：CF Div.2 A~D + 洛谷提高
- 2000+：CF Div.1 + AtCoder ARC/AGC

> 硬约束：不爬取 OJ 页面，仅生成链接

## 第十章：性能指标

| 指标 | 目标 | 测量方法 | 降级阈值 |

| OJ 题号验证耗时 | < 5 秒（5 题并发） | 计时（从生成 URL 到全部验证完毕） | > 10 秒先展示已验证的，未完成的继续验证 |

## 第十一章：开发者交接说明

### a) 实现顺序

你应按以下顺序实现：

1. **先写 `src/storage/knowledgeGraph.js`** — 数据结构 + CRUD + 聚合统计
2. **在 `background.js` 中 `onDone` 追加知识提取调用** — 用现有 `hintGenerator.analyzeReport` 类似模式做非流式提取
3. **实现聚合更新** — 每次写入后 500ms 防抖更新 `aggregates`
4. **在 `learning-plan/generator.js` 或新文件中实现阶段分析**
5. **增强 `streamPlan` 方法** — 传入知识图谱数据、约束推荐来自洛谷/CF/AtCoder
6. **实现 `src/oj-link-generator.js`** — 正则匹配 + URL 模板
7. **写侧边栏推荐面板 HTML/CSS/JS** — 复用 `plan-view` 现有结构

### b) 验收剧本

手动验证流程：

```
1. 打开 OJ 题目页，点"灵光一下"，与 AI 对话 3 轮
2. 打开 chrome.storage → 检查 key "knowledge_graph" 是否存在，records 有新增
3. 点击侧边栏 📅 按钮：
   - 首次：展示"再做 X 题解锁"（如记录 < 3）
   - 够 3 题：展示阶段分析 + 题单（含 OJ 链接）
4. 点击题单中的有效链接 → 新标签打开对应 OJ 题目页（200 OK）
5. 检查题单中每条推荐：先显示"验证中..."，然后 ✅ 可点击 或 ❌ 题号不存在
6. 打开浏览器 DevTools → Network 面板，确认 HEAD 请求发往了正确的 OJ URL
7. 故意构造一个不存在的题号（如洛谷 P99999），确认它灰显+标记"❓题号不存在"
8. "刷新"按钮 → 重新生成推荐 + 重新验证所有链接
9. 设置页 → 导出学习数据 → 下载 JSON 含完整图谱
```

### c) 已知的未知项

| 项 | 说明 | 建议 |
|----|------|------|
| AI 生成的题号可能不存在 | OJ 题目号猜测可能存在幻觉 | 使用已知题库列表做前缀验证 |
| 知识点标签归一化 | "DP" vs "动态规划" vs "Dynamic Programming" | 统一转中文，AI prompt 规范输出格式 |
| 冷启动速度 | 需 3+ 条记录才出推荐 | 用"再做 X 题"作为引导态，不阻塞使用 |
| hintLevel → 掌握度映射 | 1→0.8, 2→0.5, 3→0.2 是经验值，需调优 | MVP 用简单线性映射，后续可 AI 调参 |

### d) 给实现 AI 的特别说明

- **你不需要重构现有代码**。知识图谱是旁路系统，与现有 `history` 存储独立运行——加文件、加函数，不删不改。
- **知识点提取不要阻塞用户流程**。在 `onDone` 后的 `setTimeout(0)` 中触发，用户无感知。
- **推荐生成复用 `streamPlan` 的流式渲染机制**。不要另写一套渲染管线。
- **OJ 链接生成器要做两件事**：①正则匹配题号→生成 URL；②HEAD 请求验证题号是否存在。验证失败的条目灰显标记"题号不存在"，不展示为链接。AI 可能幻觉题号，验证是最后一道防线。
- **所有 AI 调用都走现有 config 体系**（`getConfig()`），不需要新配置项。
- **推荐 prompt 中的超链接硬约束**：AI 推荐题单的 prompt 必须包含"不给出 OJ 平台+精确题号 = 无效推荐"的惩罚性描述。宁可少推荐一道，也不出无链接条目。最终渲染时，每道题必须是一个 `<a href="URL" target="_blank">` 可点击元素——纯文本题单不符合要求。

### e) 格式约束

#### 知识点提取 JSON Schema

为保 AI 输出可解析，知识点提取 prompt 要求以下 JSON Schema：

```json
{
  "knowledgePoints": ["字符串", "模拟"],
  "difficulty": 800,
  "tags": ["字符串处理", "条件判断"],
  "masteryEstimate": 0.7
}
```

难度枚举（CF Rating）：`800` ~ `3500` 整数，步长 100 为常见间隔。
各 OJ 难度→CF Rating 映射推荐：
- AtCoder ABC A→C: 800~1200, ABC D→E: 1000~1600
- Codeforces Div.3 A: 800, B: 900, C: 1100, D: 1300, E: 1500
- Codeforces Div.2 A: 800, B: 900, C: 1200, D: 1500, E: 1900
- 洛谷 入门: 800, 普及-: 1000, 普及: 1200, 普及+: 1400, 提高: 1600, 省选: 2000+

#### 推荐输出格式约束（学习建议 + 练习题）

推荐 prompt 必须要求 AI 按以下两段式结构输出：

```
📝 学习建议：
{2-3 句话，分析薄弱点，指明改进方向，不包含题目}

✏️ 练习题：
{OJ关键词} {题号} {可选：题目名} — {知识点标签} (CF {难度分})
{OJ关键词} {题号} {可选：题目名} — {知识点标签} (CF {难度分})
...
```

**有效示例：**
```
📝 学习建议：
你最近的 DP 题目平均需要 hintLevel=2.5，说明状态转移方程还不够熟练。

**无效示例（输出格式不对）：**

只列出题目没有学习建议 ✗

推荐你做做 DP 题 ✗（无平台无题号）
```

> 硬约束：①AI 输出必须分两段——先📝学习建议再✏️练习题，缺一段则输出不合格；②练习题缺少 OJ 平台或精确题号者标记为"链接失效"灰显不可点击；③学习建议中不可混入题目（题目全部归入练习题区）。
